# FluxTerm 串口调试功能设计

## 1. 设计结论

串口采用“独立管理 Widget + 主终端工作区运行态”的结构：

1. `Serial Widget` 负责 Profile 分组管理和发起连接，端口发现集中在配置弹窗。
2. 串口会话进入 Main 持有的统一会话工作区，复用标签和 Pane 生命周期。
3. 串口会话使用结构化监视器，不创建 xterm 或 SubApp。
4. 浮动 Serial Widget 使用快照与动作代理，不持有串口会话事实源。

## 2. 分层职责

### `fluxterm-engine`（目录：`crates/engine`）

- 使用 `tokio-serial` 枚举并打开系统串口。
- 校验波特率、数据位、停止位、校验位和流控制参数。
- 维护异步读写循环、主动断开和设备异常状态。
- 保持原始字节不变，通过 `SerialOutput` 事件上报。
- 对文本发送执行 UTF-8 或 GB18030 编码。

### `src-tauri`

- 暴露 `serial_port_list`、`serial_profile_*` 和 `serial_*` 会话命令。
- 将引擎原始字节事件桥接为 `serial:output`。
- 将 Profile 和分组独立保存到 `connections/serial/profiles.json` 与 `groups.json`，不接入凭据加密。

### 前端

- Main 持有 Profile、分组、端口快照、连接动作和串口会话配置快照。
- Widget 仅展示管理入口；浮窗动作通过 `fluxterm-serial-sync` 代理回 Main。
- 会话渲染层按 `Session.kind` 分发：SSH/本地 Shell 使用 xterm，串口仅使用监视器。
- 监视器保存原始收发记录，并在文本模式下使用流式 `TextDecoder` 解码。

## 3. 会话与数据契约

统一会话类型为 `ssh | localShell | serial`。串口连接由已保存 Profile 发起；运行态使用连接时的 `SerialProfile` 快照进行命名、解码和手动重连。统一模型仍允许 `profileId` 为空，以兼容已有会话契约。

串口输出事件：

```text
serial:output {
  sessionId: string,
  data: number[],
  receivedAt: number
}
```

事件必须保留原始字节。文本模式按 Profile 编码流式解码；HEX 模式直接读取 `data`，不得从解码文本反推字节。

## 4. 调试台行为

- 监视器按后端读取批次和前端发送动作记录本地时区时间、RX/TX 和原始字节；每个显示行均使用 `[HH:mm:ss.SSS]` 展示该行首字节时间，其后显示会话内起始字节偏移量，偏移量至少四位并随数据量自动扩宽。
- 监视器使用固定行高窗口化渲染，每会话最多保留 10 MiB，超限淘汰最旧完整记录。
- 文本模式单栏显示 UTF-8/GB18030；HEX 模式将相邻同方向字节连续排布，每行固定显示 16 字节，每 4 字节使用竖向虚线分组，ASCII 使用普通等宽字符间距。HEX 字节按控制字符、可打印字符和扩展字节使用 CSS 着色，不依赖 xterm ANSI 渲染。
- 监视器仅在用户停留于底部时自动跟随新数据，用户上滚后暂停跟随。
- 文本模式按 CR/LF 和 RX/TX 方向切换生成逻辑行，长内容按视口宽度软换行；右键菜单支持复制当前选区。
- 监视器通过隐藏输入捕获层直接接收键盘、粘贴和输入法内容。文本发送按 Profile 字符集编码，Enter 使用配置的换行策略；HEX 发送解析连续或空格分隔的十六进制并写入原始字节。
- 接收显示模式与发送模式彼此独立，均可在会话右键菜单切换；清屏、复制选区和导出也位于该菜单。选择文本期间不得抢占焦点或清除浏览器选区。
- 监视器继承全局终端字体和字号配置，使串口、SSH 与本地 Shell 的字符呈现保持一致。
- 设备异常时保留前端会话内容，用户手动按原端口和原配置重连。

## 5. 能力隔离

串口不支持 PTY resize，也不启用 SFTP、远程编辑、SSH 隧道、资源监控、终端路径同步、Shell 补全、自动重连和终端 AI 上下文。由于多数平台独占打开串口，串口会话禁止“拆分并复制连接”，但可以在其他 Pane 打开不同串口。

## 6. 后续演进

首版不包含周期发送、宏脚本、协议帧解析、波形、逻辑分析和设备身份迁移。若未来形成需要独立导航、多面板和长期独占窗口的复杂调试工作流，再评估升级为 SubApp；底层串口引擎和 Profile 存储无需随窗口形态迁移。
