# 命令广播设计说明

## 1. 目标

命令广播用于向多个终端会话批量发送同一命令，支持当前会话、当前分组、全部会话三类目标范围。该能力作为标准 Widget 接入主窗口布局，并支持浮动窗口模式。

## 2. 运行时分组

会话分组是运行时状态，不写入配置文件。应用启动后固定存在默认分组，所有新建或附加的会话默认进入该分组。

自定义分组由用户在会话标题右键菜单中创建或选择。会话同一时间仅属于一个分组；移动分组时会先从原分组移除，再加入目标分组。自定义分组在最后一个会话离开或关闭后自动删除，默认分组不删除。

自定义分组拥有稳定派生的颜色，用于会话标题和命令广播状态区提示。同一分组内会话显示相同颜色，默认分组不显示额外颜色标记。

会话标题右键菜单采用软上限展示策略：默认分组固定展示，自定义分组最多直接展示 3 个；超过 3 个时提供“更多分组...”入口，通过搜索弹窗选择目标分组。分组数量本身不设置硬性上限。

## 3. 发送范围

命令广播支持以下目标范围：

1. 当前会话：仅发送到当前活动会话。
2. 当前分组：发送到当前活动会话所在分组内的全部会话。
3. 所有会话：发送到当前工作区全部会话。

实际执行前会按会话状态过滤目标，仅对可写会话发送。可写状态包括 `connected`、`connecting`、`reconnecting`。

## 4. 命令发送语义

命令广播的语义是“执行命令”，不是“填入输入行”。发送前会先清理目标终端当前输入行，再写入命令并追加回车。

清理规则如下：

1. 本地非 WSL 会话使用 `ESC`。
2. WSL、SSH 等其它会话使用 `Ctrl+U`。

命令内容会将 `LF` / `CRLF` 统一规范为 `CR`，并确保最终以 `CR` 结尾，从而在目标终端中提交执行。

单个会话写入失败不会阻断其它目标会话。执行结果目前仅用于内部计数，不在界面中展示逐会话明细。

## 5. 多次发送

命令广播支持重复发送。`发送次数` 为正整数时按指定次数执行；值为 `0` 时进入无限循环，直到用户点击停止。

`发送间隔(秒)` 限制为正数，最多保留两位小数，最小有效值为 `0.01` 秒。该限制用于避免过低间隔导致界面或终端写入压力过高。

发送过程中：

1. 命令编辑器进入只读状态，仍允许滚动、选择和复制。
2. 发送次数、发送间隔和发送范围不可修改。
3. 发送按钮切换为停止按钮。
4. 底部状态区显示发送进度。

有限次数发送完成后，进度保留到下一次发送开始。无限循环停止后，保留已发送次数。

## 6. 命令编辑器

命令输入区采用轻量编辑器实现，保留原生 `textarea` 输入能力，并增加行号栏。

编辑器行为如下：

1. 不启用软换行，行号仅对应真实换行。
2. 滚动容器位于编辑器父元素，行号和文本共享同一滚动坐标。
3. `textarea` 自身不显示边框、背景、阴影和聚焦动画，外层编辑器负责统一视觉边界。
4. 使用稳定 DOM 标记支持调试和自动化定位。

## 7. 浮动窗口同步

命令广播 Widget 可从主窗口布局浮动为独立 Tauri Webview。浮动窗口不直接持有终端运行态，而是遵循“快照 + 动作代理”模式。

主窗口通过 `fluxterm-broadcast-sync` 通道同步以下快照：

1. 当前活动会话 ID。
2. 会话列表。
3. 会话分组。
4. 会话状态。

浮动窗口发送命令时，通过同一通道向主窗口发送动作消息，由主窗口执行实际终端写入。该设计保证终端写入仍由主窗口运行时统一负责。

## 8. 接入位置

命令广播已接入以下系统边界：

1. `WidgetKey`：注册为 `broadcast`。
2. Widget 构建：通过 `buildWidgets` 注入会话、分组、状态和发送动作。
3. 懒加载入口：通过 `lazyWidgets` 独立加载。
4. 布局模型：支持主窗口停靠和浮动。
5. 国际化：提供中英文 Widget 名称、范围、进度和操作文案。

## 9. 约束

1. 分组仅在当前运行期有效，应用重启后恢复默认分组。
2. 命令广播不提供“只填入不执行”模式。
3. 默认布局不强制展示命令广播，用户可通过 Widget 选择器打开。
4. 浮动窗口中的发送动作必须代理回主窗口执行，不能绕过主窗口直接写终端。
